# Research: build-registration

- Query: Minimal build registration for `src/TranslationService.cpp` and `.h`.
- Scope: internal
- Date: 2026-09-04

## Findings

`TranslationService` is an ordinary main-executable source, not a base-library
source. Add `"TranslationService.*"` to the `files_in_dir("src", ...)` list in
`premake5.files.lua`, next to other main `src/` modules. This is the mandatory,
authoritative MSVC registration. `sumatrapdf_files()` is included by both
`SumatraPDF` and `SumatraPDF-static` projects in `premake5.lua:1347` and
`premake5.lua:1446`.

Regenerate the Visual Studio files after changing the Premake input. The
expected generated outputs are:

- `vs2022/SumatraPDF.vcxproj`: `ClCompile` for the `.cpp`; `ClInclude` for the
  `.h`.
- `vs2022/SumatraPDF-static.vcxproj`: same entries for the static/ASan target.
- `vs2022/SumatraPDF.vcxproj.filters`: matching `ClCompile` and `ClInclude`
  entries with `<Filter>src</Filter>`.
- `vs2022/SumatraPDF-static.vcxproj.filters`: matching entries with the same
  filter.

The four VS files are generated outputs, not independent hand-maintained
sources. Existing `SelectionTranslate` registration demonstrates the shape:
`vs2022/SumatraPDF.vcxproj:1277,1535`, static at
`vs2022/SumatraPDF-static.vcxproj:1249,1506`, and filters at
`vs2022/SumatraPDF.vcxproj.filters:393,1031` and
`vs2022/SumatraPDF-static.vcxproj.filters:393,1028`. No `.sln` edit is needed:
both targets already exist and `cmd/build.ts:167-170` builds `SumatraPDF`, while
`cmd/build.ts:209-213` builds `SumatraPDF-static` for ASan.

For MinGW, add `"TranslationService.*"` to the main `src` group in
`cmd/helper/mingw-build.ts` (`sumatraFiles`, near
`SelectionTranslate.*` at line 328). This is mandatory because
`buildSumatraExe()` resolves only explicit `sumatraFiles` patterns at
`cmd/helper/mingw-build.ts:490-495`; `resolveSources()` compiles only
`.c/.cpp/.cc` paths (`cmd/deps-build-common.ts:119-135`). The glob covers the
header harmlessly and picks the `.cpp`, matching local convention. Commit
`4f9ecaebd` proves a newly added normal source requires a corresponding MinGW
pattern entry.

No change is needed to `src/base` file lists, `libsumatrapdf`, linker-library
lists, solution target definitions, or `sumatraDebugExtra`: the service belongs
to the main application and must be present in debug and release.

## Ownership Boundary

One follow-up build-registration unit should own only:

- `premake5.files.lua`
- generated `vs2022/SumatraPDF.vcxproj`
- generated `vs2022/SumatraPDF-static.vcxproj`
- generated `vs2022/SumatraPDF.vcxproj.filters`
- generated `vs2022/SumatraPDF-static.vcxproj.filters`
- `cmd/helper/mingw-build.ts`

It must run after the API-core unit has created both files. It should not own
`src/TranslationService.*`, settings, HTTP code, tests, or UI files, avoiding
overlap with the API-core implementation unit.

## Caveats / Not Found

`TranslationLangs.cpp` is generated by `cmd/trans-gen.ts:229` and is explicitly
listed, but `TranslationService` is authored source and has no generator.
Do not infer registration from that special case. No additional VS project or
test project compiles ordinary `src/TranslationService.cpp` directly.
